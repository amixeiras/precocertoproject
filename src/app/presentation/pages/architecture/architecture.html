Arquitetura DDD, Clean Code & SOLID

O projeto projectprecocerto foi projetado segundo os mais rigorosos padrões de arquitetura de software empresarial, separando totalmente regras de negócio das camadas externas de infraestrutura e apresentação.

Camada de Domínio (src/app/domain)

O coração do software. Não possui dependências do Angular, HTTP ou bibliotecas externas. Contém as entidades de negócio puras, objetos de valor (Value Objects) e contratos (Ports).

Orquestra o fluxo de dados para atender os Casos de Uso (Use Cases) do sistema. Cada Use Case implementa o princípio da Responsabilidade Única (SRP) com um método execute().

S

Single Responsibility Principle (Responsabilidade Única)

Cada classe possui uma única razão para mudar. Os Casos de Uso (SearchProductsUseCase, DetectUserRegionUseCase) realizam apenas uma ação específica. Os Mappers convertem dados e nada mais. Os Value Objects validam seus invariantes e calculam valores.

O

Open/Closed Principle (Aberto para Extensão, Fechado para Modificação)

As camadas internas dependem de contratos/interfaces abstratas (ProductRepository). Para trocar de mock em memória para backend REST API, GraphQL ou Firebase, basta criar um novo repositório em infrastructure sem alterar uma linha sequer do domínio ou use cases.

L

Liskov Substitution Principle (Substituição de Liskov)

Tanto InMemoryProductRepository quanto HttpProductRepository implementam com fidelidade a interface ProductRepository, podendo ser substituídos mutuamente sem quebrar a execução do sistema.

I

Interface Segregation Principle (Segregação de Interfaces)

Interfaces enxutas e focadas no propósito do consumidor. A porta de geolocalização (GeolocationPort) é isolada dos repositórios de dados, não forçando clientes a depender de métodos desnecessários.

D

Dependency Inversion Principle (Inversão de Dependência)

Módulos de alto nível não dependem de módulos de baixo nível; ambos dependem de abstrações. Utilizamos InjectionToken do Angular para injetar as interfaces nos Casos de Uso na função providePrecoCertoInfrastructure().

Linguagem Ubíqua

Termos do domínio de negócios do Preço Certo são refletidos diretamente no código: Product, Market, PriceOffer, Region, Savings.

Padrão Result (Monad)

Elimina o lançamento de exceções não controladas em regras de domínio. O tipo Result<T, E> torna sucessos e erros explícitos na assinatura dos métodos.

Imutabilidade

Value Objects e Entidades utilizam modificadores readonly e Object.freeze(), garantindo previsibilidade e prevenindo efeitos colaterais.

Path Aliases sem Caminhos Relativos Sujos
